# 需求分析方案

> 依据：6 个岗位、24 轮访谈、36 条事实（f00–f55）+ 6 轮补充追问（f56–f61）+ 行业分析。
> 本文回答四件事：**痛点是什么 → 哪些能用 AI 改造、优先级如何 → 需求边界画在哪 → 怎么验收**。

## 一、结论摘要

| 结论 | 内容 |
|---|---|
| 痛点本质 | 不是「算不出来」，而是**口径不统一**（主键/时区/结算日）与**责任不留痕**（交接、复核、追偿） |
| AI 能做 | 线索排序（L1）、原因推荐（L2）、制度问答（RAG）、交接摘要生成——**全部只读** |
| AI 不能做 | 自动定性差错、自动调账/退款、对外承诺赔付 |
| 一期范围 | 单渠道：自动匹配 → 差异池 → 工单 → 双人复核 → 只读 AI 辅助 |
| 验收核心 | 自动匹配率 ≥ 99.9%、差异可解释率 100%、复核人 ≠ 发起人 100%、定位时长 6h → 1h |

## 二、痛点问题（按证据整理）

| # | 痛点 | 具体表现 | 证据 |
|---|---|---|---|
| P1 | **主键与时区口径不统一** | 交易号、商户订单号、渠道号关系不完整；时区不一致，有歧义记录无法直接进自动流程 | f31、f33 |
| P2 | **定位靠人翻，耗时长** | 未解释差异每天 180 笔；从发现到定位平均 6 小时；对账员每天约 5 小时查异常 | f00、f12 |
| P3 | **差错定性依赖个人经验** | 跨日退款、手续费合并入账常被误判为差错；误判会导致无效建单与无效调单 | f10、f50、f53 |
| P4 | **交接与复核不留痕** | 交接靠口头或群消息，「已转交」不等于接手；建单人与复核人常为同一人，事后说不清谁签的 | f23、f25、f40 |
| P5 | **规则与口径靠问人** | 制度散在文档与老员工记忆里，新人反复问；答复口径不一致 | f22、f24 |
| P6 | **追偿窗口无人盯** | 7 天窗口没有前置提醒，发现即超期，只能内部消化 | f42、f44 |

## 三、AI 改造点与优先级

判据有三条：**能不能降低人工量**、**出错时能不能被人拦住**、**数据够不够**。三条都满足才进一期。

| # | AI 改造点 | 能力级别 | 解决痛点 | 一期 | 优先级理由 |
|---|---|---|---|---|---|
| A1 | **差异线索排序**：给出 Top-5 候选关联记录 + 字段级差异对比 | L1 只读 | P2 | 是 | 只影响查看顺序，错了也不产生业务后果；数据现成 |
| A2 | **原因推荐**：七类中的候选原因 + 证据引用 + 置信度 | L2 只读 | P3 | 是 | 定性仍由人工确认，模型只提供候选；可显著减少误分类 |
| A3 | **制度问答（RAG）**：对账口径、差错处理规范可检索，回答带条款引用 | L1 只读 | P5 | 是 | 纯读、零风险；把「问人」变成「问系统」 |
| A4 | **交接摘要生成**：自动汇总差异上下文、已做动作、待确认事项 | L1 只读 | P4 | 是（P1） | 支撑交接五要素，但不替代接手确认 |
| A5 | **异常模式识别**：重复单、金额离群、未知收款方的统计识别 | L1 只读 | P3 | 二期 | 需要历史样本沉淀，一期样本不足 |
| A6 | **动作建议**（补单/退款/调账文本） | L3 | P2 | **否** | 涉及资金判断，一期不交付，二期评估且需双人复核 |
| A7 | **自动执行**（自动调账/退款） | L4 | —— | **禁止** | 与「只读不改资金」硬约束冲突 |

**优先级结论**：一期只做 A1–A4，全部是只读能力；A5 二期；A6 需二期评估；A7 永不进入范围。

## 四、需求边界

### 4.1 范围

| 做 | 不做（明确排除） |
|---|---|
| 单渠道拉单、解析、批次管理 | 资金划拨、代付、退款执行 |
| 明细逐笔匹配 + 汇总核对 | 会计凭证生成 |
| 七类差错初判 + 证据链 | 自动定性为最终结论 |
| 差异池、工单、交接、SLA 升级 | 商户结算规则、费率配置 |
| 双人复核、结算文件生成 | 替代支付网关的交易能力 |
| 只读 AI（排序 / 推荐 / 问答 / 摘要） | 对外承诺赔付、直接答复商户 |

### 4.2 三条不可退让的硬约束

1. **只读不改资金**：系统不发起退款、调账、划拨，只输出差异与线索；资金动作跳转原有系统。
2. **结论必须人签**：规则与 AI 只给候选，定性与复核由人签字；复核意见必填，发起人 ≠ 复核人。
3. **审计可重建**：每条差异可按业务编号回溯到原文、规则版本、模型调用记录与处理人。

## 五、需求规格

| 编号 | 需求 | 优先级 | 验收要点 |
|---|---|---|---|
| REQ-1 | 先统一主键与时区口径，再进入差异定位辅助 | P0 | 歧义记录进人工修复队列，不进自动流程 |
| REQ-2 | 差异定位辅助限定为只读线索排序，不生成资金结论 | P0 | 无任何写资金接口；建议必须能点回原记录 |
| REQ-3 | 差异定位到工单确认的交接责任需显式化 | P1 | 交接五要素齐全，接手人确认才算完成 |
| REQ-4 | 人工兜底触发条件与接手时限需可审计 | P1 | 触发即记录原因、接手人、确认时间，超时升级 |
| REQ-5 | 服务侧口径分歧需在答复中显式标注 | P2 | 答复带「结算日/支付日」口径标注 |
| REQ-6 | 验收指标需先定义「匹配正确」与「差异可查原因」 | P1 | 指标口径书面化、分母排除规则固定 |

## 七、验收标准清单

| # | 指标 | 计算口径 | 目标 | 验证方式 |
|---|---|---|---|---|
| 1 | 自动匹配率 | 自动匹配成功笔数 / 应匹配笔数（剔除歧义） | ≥ 99.9% | 历史数据回放 |
| 2 | 匹配准确率 | 抽样人工复核判定正确的比例 | ≥ 99.5% | 抽 1000 笔人工核 |
| 3 | 差异可解释率 | 有证据且已分类的差异 / 全部差异 | 100% | 全量校验 |
| 4 | 未解释差异 | 每日未归因差异笔数 | ≤ 40 笔 | 连续 2 周统计 |
| 5 | 定位时长 | 账单入库至差异定性 P90 | ≤ 1 小时 | 埋点统计 |
| 6 | 复核合规率 | 复核人 ≠ 发起人的单据占比 | 100% | 日志审计 |
| 7 | 批次成功率 | 按时完成批次数 / 应完成批次数 | ≥ 99% | 调度日志 |
| 8 | 重跑正确性 | 重跑结果与首次一致率 | 100% | 抽样重跑比对 |

**验收前置条件**：指标 1 的「匹配正确」必须先书面定义四要素（主键一致、金额容差、时间窗、状态一致），否则分母不可比，验收无法结项——这一条本身就是 REQ-6。

## 八、假设、风险与开放问题

| 类型 | 内容 | 处理 |
|---|---|---|
| 假设 | 一期只接 1 个渠道，日 80 万笔 | 二期扩展需重估容量 |
| 假设 | 渠道提供标准结算文件（CSV/Excel） | 非标格式需单独报价 |
| 风险 | 口径字典没人维护 → 匹配率虚高 | 指定维护人 + 版本变更审批 |
| 风险 | AI 推荐被当成结论使用 | 界面强提示「未验证」，定性必须人工勾选 |
| 开放问题 | 匹配正确由谁定义、差异原因由谁确认 | 需运营经理与风险经理书面确认 |
| 开放问题 | 跨渠道对账是否进二期 | 待二期立项评审 |
