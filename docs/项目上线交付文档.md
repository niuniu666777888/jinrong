## 二、运行手册

### 2.1 部署拓扑

| 组件 | 规格 | 数量 | 说明 |
|---|---|---|---|
| 应用服务 | 8C16G | 2 | 无状态，前置 Nginx 做负载与 TLS 终止 |
| 数据库 | 8C32G / SSD 1TB | 1 | PostgreSQL 15，按日 + 渠道分区 |
| 对象存储 | 2TB | 1 | 原始账单与证据附件，开启版本化 |
| 备份存储 | 2TB | 1 | 数据库全量 + WAL 归档，异地保留 30 天 |

网络：仅内网访问，不出网；模型服务部署在同一内网段。

### 2.2 启动与停止

| 动作 | 命令 / 操作 | 校验 |
|---|---|---|
| 启动 | `systemctl start jinrong-app`（两节点依次） | `GET /api/v1/health` 返回 `ready` |
| 停止 | `systemctl stop jinrong-app` | 确认无进行中的对账批次 |
| 重启 | 先摘流量 → 重启 → 健康检查通过后挂回 | 观察 5 分钟错误率 |
| 日志 | `/var/log/jinrong/app.log`，按日轮转，保留 30 天 | —— |

**停止前必须确认**：无 `running` 状态的批次；无 `submitted` 待复核工单（否则复核计时中断）。

### 2.3 日常巡检

| 频率 | 检查项 | 正常值 | 异常处置 |
|---|---|---|---|
| 每日 08:30 | 当日批次是否创建 | 批次状态 `待文件`/`对账中` | 未创建 → 查调度日志 → 手工触发 |
| 每日 09:00 | 拉单成功率 | 100% | 失败 ≥ 3 次 → 按 2.5 场景 A 处理 |
| 每日 | 差异量 | 与基线偏差 ≤ 30% | 突增 → 查口径字典变更与账单完整性 |
| 每周一 | 磁盘与备份 | 使用率 < 80%，备份成功 | 清理归档 / 重跑备份 |
| 每周 | 审计日志完整性 | 哈希链校验通过 | 校验失败 → 立即上报安全负责人 |
| 每月 | 账号与权限复核 | 与权限清单一致 | 差异 → 冻结账号并走变更 |

### 2.4 监控与告警

| 指标 | 阈值 | 告警级别 | 通知对象 |
|---|---|---|---|
| 批次成功率 | < 99% | P2 | 运维值班 |
| 对账任务时长 | > 2 小时 | P2 | 运维 + 研发 |
| 差异量 | > 基线 2 倍 | P1 | 运营经理 + 运维 |
| 接口错误率 | > 1%（5 分钟） | P1 | 运维 |
| 数据库连接数 | > 80% | P2 | 运维 |
| 复核超时 | 超过 SLA 时限 | P3 | 责任人 + 主管 |

### 2.5 故障处置

| 场景 | 判定 | 处置 | 升级 |
|---|---|---|---|
| A. 渠道文件未到 | 超 T+1 10:00 仍无文件 | 致电渠道对接人 → 拿到后手工上传 → 重跑批次 | 2 小时未解决 → 运营经理 |
| B. 文件格式变更 | 解析失败率 > 5% | 停止入库、保留原文 → 调整解析模板 → 重跑 | 4 小时未解决 → 数据工程师 |
| C. 数据库不可用 | 连接超时 | 切备库 → 只读模式对外 → 恢复后补写 | 立即 → DBA + 负责人 |
| D. 对账结果异常 | 差异量突增 2 倍 | 暂停建单 → 核对口径字典与账单版本 → 确认后放行 | 立即 → 运营 + 风险 |
| E. 误操作已建单 | 工单已提交 | 退回 → 记录原因 → 复核人拒签 → 重新核验 | 当日 → 主管 |

**通用原则**：先止损（暂停写操作），再定位，最后补数据；所有处置动作写入工单事件。

### 2.6 备份与恢复

| 项 | 策略 | 恢复目标 |
|---|---|---|
| 数据库全量 | 每日 02:00 | RPO 24h，RTO 2h |
| WAL 归档 | 持续 | RPO 15min |
| 对象存储 | 版本化 + 跨区复制 | RPO 1h |
| 配置与密钥 | 变更即备份，加密存储 | RTO 30min |

演练：每季度一次，随机抽取 1 个批次做恢复并比对结果。

### 2.7 变更与回滚

1. 变更单 → 影响评估 → 灰度（1 个渠道/1 天）→ 全量；
2. 回滚窗口：发布后 30 分钟内可一键回滚到上一镜像；
3. 数据库变更只允许向前兼容（先加字段，后删字段）。

### 2.8 常见问题

| 问题 | 原因 | 处理 |
|---|---|---|
| 批次一直「待文件」 | 渠道未推送或推送目录变更 | 查渠道后台 → 手工上传 |
| 差异全部为「金额不符」 | 手续费规则变更未同步口径字典 | 更新字典版本 → 重跑 |
| 工单提交被拒 | 建单人与提交人相同 | 换人操作（系统强制） |
| AI 建议为空 | 模型服务不可用或样本不足 | 检查模型服务；不影响主流程 |
| 导出超时 | 数据量大 | 缩小时间范围或走异步导出 |

## 三、培训方案

### 3.1 对象与目标

| 对象 | 人数 | 目标 | 课时 |
|---|---|---|---|
| 对账会计 | 4 | 独立完成差异核验、建单、提交 | 4 小时 |
| 渠道运营员 | 2 | 处理渠道侧异常、催单、上传账单 | 2 小时 |
| 资金风险经理 | 1 | 理解红线、停止条件、复核与抽查 | 2 小时 |
| 商户服务主管 | 1 | 口径标注、争议受理 | 1.5 小时 |
| 系统管理员 / 运维 | 2 | 部署、巡检、故障处置、备份恢复 | 6 小时 |

### 3.2 课程安排

| 课次 | 主题 | 形式 | 时长 |
|---|---|---|---|
| 1 | 业务背景与痛点（为什么改） | 讲授 | 1h |
| 2 | 系统操作：批次、差异、工单、复核 | 演示 + 上机 | 2h |
| 3 | AI 辅助的边界（什么能信、什么必须人判） | 案例研讨 | 1h |
| 4 | 权限与职责分离、审计要求 | 讲授 + 测验 | 1h |
| 5 | 运维：巡检、故障、备份恢复 | 演练 | 6h |

**上机环境**：与生产同构的演练环境，使用脱敏历史数据。

### 3.3 考核

| 角色 | 考核方式 | 通过标准 |
|---|---|---|
| 对账会计 | 在演练环境完成 3 笔差异全流程 | 全部通过且复核合规 |
| 运维 | 模拟「渠道文件未到」+「数据库切换」 | 30 分钟内恢复 |
| 风险经理 | 口述停止条件与叫停流程 | 与文档一致 |

未通过者不得授予生产权限。

### 3.4 培训材料

- 课件 PPT（5 份）
- 操作手册（图文，含截图）
- 演练脚本与数据集
- 常见问题速查卡（一页纸）

## 四、权限清单

### 4.1 角色

| 角色 | 数据域 | 说明 |
|---|---|---|
| 支付运营经理 | 全部渠道 | 目标与验收负责人，可发起试点 |
| 渠道运营员 | 本人负责渠道 | 一线操作、催单、上传 |
| 对账会计 | 全部渠道（只读+差异处理） | 差异核验、建单、提交 |
| 支付数据工程师 | 全部渠道（配置） | 口径字典、解析模板 |
| 资金风险经理 | 全部渠道（只读+复核） | 红线与停止条件、复核签核 |

| 系统管理员 | 系统配置 | 用户与权限，**不可操作业务单据** |

| 维护口径字典 | — | — | — | ✓ | 审批 | — | — |
| 导出明细 | ✓ | — | ✓ | — | ✓ | — | — |
| 用户与权限 | — | — | — | — | — | — | ✓ |

### 4.3 职责分离（系统强制）

1. 建单人 ≠ 复核人，提交复核时服务端拦截；
2. 系统管理员不可建单、不可复核（避免既管权限又管业务）；
3. 口径字典变更需数据工程师提交、风险经理审批；
4. 明细导出需二次确认，单次超 1 万条需风险经理审批。

### 4.4 账号管理

| 场景 | 流程 | 时限 |
|---|---|---|
| 开通 | 主管申请 → 管理员创建 → 首次登录强制改密 | 1 工作日 |
| 变更 | 变更单 → 管理员调整 → 留痕 | 1 工作日 |
| 离职 | HR 触发 → 当日禁用 → 权限回收确认 | 当日 |
| 审计 | 每季度复核一次账号与权限，输出复核报告 | 季度 |
