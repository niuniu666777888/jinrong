## 2. 项目基本情报

一份汇总文档（`.md` 阅读 / `.docx` 提交），把散在各处的背景信息收敛成十章：

1. **问题**——对账为什么对不上：跨日退款、手续费合并入账、主键与口径不一致
2. **范围**——做什么 / 明确不做什么
3. **十条架构决策**——系统边界、主键与时区、规模时效、差错定性、AI 边界、角色权限等
4. **角色与职责分离**——六岗 RBAC，以及四条由系统强制的硬约束
5. **口径**——三个编号（业务键 / 资金键 / 系统键）与四条时间轴
6. **七类差错与处理**——长款、短款、金额不符、状态不符、重复单、跨日退款、手续费/汇率差异
7. **验收指标**——自动匹配率 ≥ 99.9%、差异可解释率 100%、未解释差异 180 → 40 笔等
8. **三条不可退让的硬约束**——只读不改资金、结论必须人签、审计可重建
9. **数据与技术**——合成数据说明、选型、部署合规
10. **来源**——访谈记录、需求规格、行业资料的对应关系

## 3. 典型事件访谈（资金风险经理 傅景）

针对「对账差错处理的红线怎么落地」做了 6 轮追问，每轮都要求给出可执行的口径与阈值：

1. 四眼原则怎么落到系统里？夜班只有一个风险岗时例外怎么走？
2. 什么情况下叫停？阈值多少、谁有权恢复？
3. 差异金额多大必须走资金调整？多少可以账务订正、多少可以批量核销？
4. 模型给出的建议能不能直接写进工单？换版要不要重新验证？
5. 审计要能重建什么？留存多久、要不要防篡改？
6. 跨月、跨年的差异怎么处理？渠道侧的差错怎么追偿？

| 文件 | 说明 |
|---|---|
| `典型事件访谈.txt` | 原始访谈记录，纯文本、可直接下载打开，未做删改 |
| `典型事件访谈.docx` | 用 AI 工具整理成稿：问题背景、角色要点、量化口径、逐轮实录、新增事实（`f56`–`f61`）、待澄清项，以及「追问结论 vs 仓库 `src/` 实现」的差距对照 |

## 4. 两份流程图
