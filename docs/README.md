# docs 目录说明

「工程技术与创新应用项目汇总」的文档部分，按八项交付要求组织：

| # | 交付要求 | 文件 |
|---|---|---|
| 1 | 六人访谈记录（`*.md` `*.json` `*.csv`） | `六人访谈记录.md`、`.json`、`.csv` |
| 2 | 项目基本简报等信息 | `项目基本情报.md`、`项目基本情报.docx` |
| 3 | 典型事件访谈（≥2–3 轮）<br>(1) 可直接下载的 `*.txt`<br>(2) AI 整理成 `docx` | `典型事件访谈.txt`、`典型事件访谈.docx` |
| 4 | 行业分析文档（`.md` + `.docx`） | `行业分析文档.md`、`行业分析文档.docx` |
| 5 | 两份流程图：改造前 / 改造后 | `流程图_改造前.html` / `.png`、`流程图_改造后.html` / `.png` |
| 6 | 需求定义文档（`.docx`） | `需求分析方案.md`、`需求分析方案.docx` |
| 7 | 详细项目设计方案 | `详细项目设计方案.md`、`详细项目设计方案.docx` |
| 8 | 报价（低 / 中 / 高）与投入产出测算 | `项目报价与投入产出测算.md`、`项目报价与投入产出测算.docx` |

> 格式说明：`.md` 便于在 GitHub 直接阅读与 diff，`.docx` 为提交用排版稿，两者内容一致。
>
> 数据性质：**合成场景**。受访人姓名、单位、金额与差错记录均为演示数据，不代表真实客户；
> 需求结论均为待验证假设。

## 1. 六人访谈记录

同一份记录的三种格式：

| 文件 | 形态 | 用途 |
|---|---|---|
| `六人访谈记录.md` | 六章正文，每章七节 | 直接阅读 |
| `六人访谈记录.json` | 结构化：6 人 × 24 轮问答 + 36 条事实 | 程序读取、二次加工 |
| `六人访谈记录.csv` | 一行一轮问答（9 列，UTF-8 BOM） | Excel 打开、做统计 |

6 个岗位：顾明岚（支付运营经理）、林亦舟（渠道运营员）、唐映秋（对账会计）、
秦芮（支付数据工程师）、傅景（资金风险经理）、叶书（商户服务主管）；
共 24 轮问答、36 条事实（`f00`–`f55`）、6 条候选需求（REQ-1～REQ-6）。

## 2. 项目基本情报

十章的汇总文档：问题与根因、范围（做/不做）、十条架构决策、角色与职责分离、
三个编号与四条时间轴、七类差错与处理、验收指标、三条硬约束、数据与技术、来源。

## 3. 典型事件访谈（资金风险经理 傅景）

共 **7 轮**，分两部分：

- **第 1–6 轮**：围绕「红线怎么落地」的追问，每轮要一个可执行口径——四眼原则落地、
  停止条件与叫停权、金额分层与容差、AI 输出边界与换版、审计证据链、跨期处理与渠道追偿；
- **第 7 轮**：平台问答原样导出（2026-11-06），主题是**审计凭证与追溯修改**——
  要求任何人工改动都能对上原始建议和签核人，并留下「改动前后值 + 改动原因 + 签核人」。

| 文件 | 说明 |
|---|---|
| `典型事件访谈.txt` | 原始记录，纯文本、可直接下载；第 1–6 轮为推演素材，第 7 轮为平台导出原文，均未改写 |
| `典型事件访谈.docx` | AI 整理稿：问题背景、角色要点、量化口径、逐轮实录、新增事实（`f56`–`f61`）、待澄清项，以及「追问结论 vs 仓库 `src/` 实现」的差距对照 |

> 第 7 轮没有新增事实编号，复用 `f40`（资金调整双人复核）与 `f45`（审计可重建），
> 因此追溯矩阵无需变更。

## 4. 行业分析文档

追偿有窗口、AI 只做辅助、审计即产品）。

## 6. 需求分析方案

按「痛点 → AI 改造点与优先级 → 需求边界 → 需求规格 → 追溯矩阵 → 验收清单」组织：

- 七个痛点（P1–P7），每条挂量化基线与访谈证据编号；
- 七个 AI 改造点（A1–A7），按「价值 / 可拦截性 / 数据可得性」加权排序：
  一期只做 A1–A4（全部只读），A5 二期，A6 二期评估，A7 禁止；
- 需求边界（系统边界图、做/不做、三条硬约束）与 REQ-1～REQ-7 规格；
- **需求追溯矩阵**：痛点 → 需求 → 证据 → 功能 → 验收指标 → 验证方式，并做追溯完整性检查；
- 验收标准清单：9 项指标 + 计算口径 + 数据来源 + 判定规则（4 项硬门槛）。

## 7. 详细项目设计方案

设计原则、六层总体架构、八个模块划分、对账流水线与差异状态机、核心数据表、
接口清单、AI 方案（L1–L4 边界与工程约束）、非功能设计、部署架构、五条关键取舍。

## 8. 项目报价与投入产出测算

按「报价及范围 → 月运行成本 → 业务量/节省时间/采用率 → 首年净收益、ROI、回本期 → 待验证假设」五段组织，
所有数字由 `analysis/roi_model.py` 计算、`analysis/tests/` 校验（21 条用例）：

- 三档报价：**低 12 万 / 中 26 万 / 高 130 万**，各档范围、周期、交付物与月运行成本；
- 月运行成本拆成运维人力、基础设施、模型接口三项（中档 0.60 万/月）；
- 采用率按 12 个月爬坡（30% → 50% → 70% → 80% 稳态），收益只算工时与追偿；
- 首年净收益：**低 5.55 / 中 3.78 / 高 −71.88 万**；回本期 **9 / 11 / 超过 24 个月**；
  稳态年净 19.8 / 33.6 / 66.0 万；
- 待验证假设 H1–H7 + 二维敏感性（采用率 × 改造后工时）。
